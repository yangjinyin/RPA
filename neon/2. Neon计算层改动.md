## Neon PostgreSQL 改动总结

### 一、核心架构改动

#### 1. **Storage Manager (SMGR) 扩展**

在传统 Postgres 中，存储是通过 `smgr`（Storage Manager）接口与本地文件系统（POSIX）交互的。

- **核心改动：** Neon 引入了一个自定义的存储扩展，挂钩（Hook）了 `smgr` 接口。
- **应用场景：** 当 Postgres 需要读取或写入数据页（Page）时，Neon 不再调用 `read()` 或 `write()` 本地磁盘，而是将请求封装成 RPC 调用。这意味着对于 Postgres 核心而言，磁盘不再是挂载在 `/var/lib/postgresql/data` 下的文件，而是一个**远端的可编程服务（Pageserver）**。



#### 2. 写路径改动：WAL 拦截与 Safekeeper 机制

在原生 Postgres 中，WAL（预写日志）是确保 ACID 的关键，由 `XLogInsert` 写入本地磁盘。

- **核心改动：** Neon 拦截了 WAL 的落盘过程，将其异步流式传输给 **Safekeeper** 集群。
- **应用场景：** Neon 并没有修改 WAL 的逻辑格式（保持了 100% 兼容），但它改变了持久化的含义。只有当 WAL 被 Safekeeper 集群（基于 Paxos 协议）确认接收后，计算节点才认为事务提交成功。这让计算节点变得“无状态”，因为它不需要在本地保留任何事务记录。

#### 3. 读路径改动：GetPage@LSN 范式

这是 Neon 最具创新性的改动。

- **核心改动：** 当 Postgres 发生 Buffer Miss（缓存未命中）需要从磁盘读页时，它发出的不再是“给我文件 X 的第 Y 块”，而是“**给我文件 X 在 LSN（日志序列号）为 Z 时的第 Y 块数据**”。
- **应用场景：** 通过在读请求中携带 LSN，Neon 实现了**存储层的多版本并发控制（MVCC）**。这使得计算节点可以瞬间完成“快照克隆”或“分支创建”，因为存储层可以根据指定的 LSN 现场重放（Redo）日志，拼凑出任何历史时刻的数据页。



### 4. 引入本地文件缓存（Local File Cache, LFC）

由于存储在远端，网络延迟（通常从微秒级跳到毫秒级）是最大的性能杀手。

- **核心改动：** Neon 在 Postgres 的 `Shared Buffers` 之下、远端存储之上，增加了一个基于本地 NVMe 的 **LFC 层**。
- **应用场景** 这是一个可动态伸缩的缓存层。它解决了存算分离架构下的延迟抖动问题。由于 LFC 的存在，热数据依然能在本地命中，而冷数据才去远端抓取。这对于支持“缩容至零（Scale-to-Zero）”后的快速冷启动至关重要。



### 5. 内核级的预取优化（Prefetching）

原生 Postgres 依赖操作系统的预读（Read-ahead）机制来优化顺序扫描。

- **核心改动：** Neon 修改了 Postgres 内核中执行计划（如 Sequential Scan, Index Scan）的底层代码，加入了显式的**异步预取（Async Prefetching）**。
- **应用场景：** 在云原生存储环境中，操作系统预读失效了。Neon 必须让 Postgres 提前预知接下来的数据页需求，并通过管道化（Pipelining）发起并发网络请求，以抵消网络往返时间（RTT）对吞吐量的影响。

##  2.2 核心函数改动

#### smgrinit() - 初始化阶段

**Before**:
```c
void smgrinit(void) {
    int i;
    for (i = 0; i < NSmgr; i++)
        if (smgrsw[i].smgr_init)
            smgrsw[i].smgr_init();      // 循环初始化所有SMGR
    
    on_proc_exit(smgrshutdown, 0);      // 注册关闭钩子
}

static void smgrshutdown(int code, Datum arg) {
    int i;
    for (i = 0; i < NSmgr; i++)
        if (smgrsw[i].smgr_shutdown)
            smgrsw[i].smgr_shutdown();
}
```

**After**:
```c
void smgrinit(void) {
    (*smgr_init_hook)();  // 调用钩子函数(默认smgr_init_standard)
}

// 新的全局变量
smgr_init_hook_type smgr_init_hook = smgr_init_standard;
smgr_shutdown_hook_type smgr_shutdown_hook = NULL;

// 标准实现
void smgr_init_standard(void) {
    mdinit();           // 仅初始化md(磁盘管理)
}

void smgr_shutdown_standard(void) {
    /* no-op */        // 标准SMGR不需要关闭
}
```

## 2.3 新增函数:

```c
// 这是新增的核心函数 - 动态获取正确的SMGR实现
const f_smgr *
smgr(ProcNumber backend, RelFileLocator rlocator)
{
    const f_smgr *result;
    
    // 如果扩展提供了 smgr_hook,使用扩展的实现
    if (smgr_hook)
        result = (*smgr_hook)(backend, rlocator);
    else
        result = smgr_standard(backend, rlocator);  // 否则使用标准实现
    
    return result;
}

// 标准实现
const f_smgr *
smgr_standard(ProcNumber backend, RelFileLocator rlocator)
{
    return &smgr_md;  // 返回磁盘管理SMGR
}
```
