# 1. Prune partition

 分区裁剪只受到where 条件过滤和 关联条件的影响。因此不依赖于执行计划



## 1.1 范围分区

遍历每一个分区的范围，将于取值范围存在相交的分区 标记即可



## 1.2 哈希分区

1. 如果是准确值，可以通过计算hash后，判断在哪个分区，标记分区即可

2. 如果是范围条件，则将所有分区标记为 需要



## 1.3 调用堆栈

```c++
|-->prune_partition()
|	|-->1. 如果没有用于 分区裁剪 的条件，则将所有分区标记为需要
|	|-->2. create_partition_index_description() //创建 分区索引描述,如果分区或子分区中使用了 BLOB 或 Geometry 类型字段，则不会对这些分区进行裁剪
|	|-->3. get_mm_tree()//范围分析器用于寻找单个或多个索引访问的范围访问
|	|-->4. tree->type == SEL_TREE::IMPOSSIBLE //查询条件恒为假，将所有分区标记为不需要
|	|-->5. tree->type == SEL_TREE:ALWAYS //查询条件恒为真，将所有分区标记为需要
|	|-->6. tree->merges.is_empty()//单个索引
|	|	|-->find_used_partitions() //然后根据SEL_ARG与prune_param比较确定分区(设置read_partitions)
|	|-->7. tree->merges.elements == 1 //若干个区间列表的合并，tree1 OR tree2 OR tree3
|	|	|-->find_used_partitions_imerge() //分别计算每一个区间所需要的分区，并求这些分区的并集
|	|-->8.tree->merges.elements > 1 //tree1 AND tree2 AND tree3
|	|	|-->find_used_partitions_imerge_list()//使用位图（bitmap）求这些区间的交集
|	|-->9.pprune_cond->const_item()//如果条件是常量，或者在执行阶段，标记裁剪完成否则，可能需要在优化阶段再次执行裁剪
    
```

## 1.4 get_mm_tree

构建单个或者多个 key part 的红黑树，其中 SEL_TREE::keys 是存储一个个单个 key part 的红黑树，SEL_TREE::merges 是存储多个 key part 的范围红黑树， SEL_TREE 节点类型是 SEL_ARG。



```c++
class SEL_ARG {
public:
   ......
  SEL_ARG *left, *right; //孩子节点，用于连接同一key的不同区间节点
  SEL_ARG *next, *prev;  //用于同一个key上关系，表示逻辑上OR的关系
  SEL_ARG *parent{nullptr}; /* R-B tree parent (nullptr for root) */
  /*
    R-B tree of intervals covering keyparts consecutive to this
    SEL_ARG. See documentation of SEL_ARG GRAPH semantics for details.
  */
  SEL_ROOT *next_key_part{nullptr};//指向下一个key part的，用于AND 关系
  uchar *min_value, *max_value;  // range的范围[23,23]  
  
   ......
};
```



eg:

```
SELECT *
FROM t1
WHERE (kp1 < 1
    AND kp2 = 5
    AND (kp3 = 10
    OR kp3 = 12))
    OR (kp1 = 2
    AND (kp3 = 11
    OR kp3 = 14))
    OR (kp1 = 3
    AND (kp3 = 11
    OR kp3 = 14));
```

### get_ne_mm_tree 函数

针对于 SEL_TREE for <> or NOT BETWEEN 条件构造mm tree kp1 <> 1 => kp1 < 1 or kp1 > 1

tree_or(kp1 < 1 , kp1 > 1)



### get_func_mm_tree_from_in_predicate 函数

通过IN value构造mm tree

NOT IN是有可能把内存oom的，因此not in的个数NOT_IN_IGNORE_THRESHOLD的控制，小于这个阈值，创建mmtree，否则返回null



### tree_and 函数

遍历所有keys，通过key_and合并 tree1和tree2



### tree_or 函数

遍历所有keys，通过key_or合并 tree1和tree2 a) 可能产生简单的range (in tree->keys[]) b) 可能产生index merge range(in tree->merges)



### key_and 函数

尽可能合并 SEL_ARG “key1 AND key2” . kp1 > 1 and kp1 < 5 (sel_arg1(min_value=1) and sel_arg2(max_value=5)) —-> 1 < kp1 < 5 (new_sel_arg(min_value=1, max_value=5))

kp1 > 1 and kp1 > 5 (sel_arg1(min_value=1) and sel_arg2(min_value=5)) —-> kp1 > 5 (new_sel_arg(min_value=5))



### key_or 函数

尽可能合并 SEL_ARG “key1 OR key2” . => expr1 OR expr2. 对于重叠的子范围，递归key_or： (1) ( 1 < kp1 < 10 AND 1 < kp2 < 10 ) (2) ( 2 < kp1 < 20 AND 4 < kp2 < 20 ) key_or( 1 < kp2 < 10, 4 < kp2 < 20 ) => 1 < kp2 < 2

## 2.2 索引扫描

有序扫描：

1. 会申请一个 **uchar \*Partition_helper::m_ordered_rec_buffer**  用于排序的buffer 。结构如下
2. 采用了堆排序，先从所有分区各获得一条数据放到m_ordered_rec_buffer各自位置。然后m_queue 排序，m_queue内容只记录各分区位置
3. top后，会读取part_id赋值给m_top_entry作为下次要读取的分区
4. handle_ordered_next()循环读取时第一步就根据m_top_entry作为读取分区

```C++
class Partition_handler {
	TABLE *m_table;    //扫描表

  /** All internal partitioning data! @{ */
  /** Tables partitioning info (same as table->part_info) */
  partition_info *m_part_info;  				//扫描分区
  /** Is primary key clustered. */
  bool m_pkey_is_clustered;
  /** Cached value of m_part_info->is_sub_partitioned(). */
  bool m_is_sub_partitioned;
  /** Total number of partitions. */
  uint m_tot_parts;			//总分区数
  uint m_last_part;        // 最后访问的分区
  const uchar *m_err_rec;  // 记录error buf
 
  /** Row and key buffer for ordered index scan. */
  uchar *m_ordered_rec_buffer;					//排序的空间 （2+每条记录）* 分区数目。这样节省空间。效率比较低？
  /** Prio queue used by sorted read. */
  Prio_queue *m_queue;							//最小堆
  /** Which partition is to deliver next result. */
  uint m_top_entry;								//下一次要扫描的partid
  /** Offset in m_ordered_rec_buffer from part buffer to its record buffer. */
  uint m_rec_offset;							//rec_buffer 在排队缓冲区的偏移位置
}
```



m_ordered_rec_buffer：用来排序的buffer空间。（2+每条记录长度）* 分区数

```c++
 */
	
```

## 2.3 range扫描

range scan的范围由变量`mrr_cur_range.start_key` 和` mrr_cur_range.end_key`决定。
