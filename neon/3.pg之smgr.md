# 1.核心概念

**SMGR（Storage Manager）** 是 PostgreSQL 中管理物理存储文件的抽象层，位于缓冲区管理器和文件系统之间，提供了统一的接口来操作关系文件。

![image-20260115155903862](C:\Users\yangjinyin\AppData\Roaming\Typora\typora-user-images\image-20260115155903862.png)					

```c++
  Buffer Manager
      ↓
  smgrread/write (smgr.c)
      ↓
  mdreadv/writev (md.c)
      ↓
  _mdfd_getseg (获取段)
      ↓
  FileRead/Write (fd.c)
      ↓
  Operating System
```

**段管理**：pg 将大表分割成多个段文件，这样做是为了更容易支持大于操作系统文件大小限制的原因(通常2G)。

​		（1）每个文件都比操作系统文件大小限制要小，段大小由`pg_conf.h`中的RELSEG_SIZE控制，一般是1G。

​		 （2）文件命名：`relfilenode`, `relfilenode.1`, `relfilenode.2`...

​		  （3）按需打开段文件，不是一次性打开所有段

# 3. 核心函数

## smgr核心函数

**`smgrinit()`** 

- 后端启动时调用
- 初始化各存储管理器（目前只有 md）
- 注册 shutdown 钩子

**`smgropen(RelFileLocator, ProcNumber)`** 

- **核心方法**：获取或创建 SMgrRelation 对象
- 不实际打开底层文件
- 在哈希表中查找或创建条目
- 对象生命周期延续到事务结束
- 返回的指针在事务内保持有效

```c
SMgrRelation
smgropen(RelFileLocator rlocator, ProcNumber backend)
{
	RelFileLocatorBackend brlocator;
	SMgrRelation reln;
	bool		found;

	Assert(RelFileNumberIsValid(rlocator.relNumber));

	if (SMgrRelationHash == NULL)
	{
		/* First time through: initialize the hash table */
		HASHCTL		ctl;

		ctl.keysize = sizeof(RelFileLocatorBackend);
		ctl.entrysize = sizeof(SMgrRelationData);
		SMgrRelationHash = hash_create("smgr relation table", 400,
									   &ctl, HASH_ELEM | HASH_BLOBS);
		dlist_init(&unpinned_relns);
	}

	/* Look up or create an entry */
	brlocator.locator = rlocator;
	brlocator.backend = backend;
	reln = (SMgrRelation) hash_search(SMgrRelationHash,
									  &brlocator,
									  HASH_ENTER, &found);

	/* Initialize it if not present before */
	if (!found)
	{
		/* hash_search already filled in the lookup key */
		reln->smgr_targblock = InvalidBlockNumber;
		for (int i = 0; i <= MAX_FORKNUM; ++i)
			reln->smgr_cached_nblocks[i] = InvalidBlockNumber;
		reln->smgr_which = 0;	/* we only have md.c at present */

		/* it is not pinned yet */
		reln->pincount = 0;
		dlist_push_tail(&unpinned_relns, &reln->node);

		/* implementation-specific initialization */
		smgrsw[reln->smgr_which].smgr_open(reln);
	}

	return reln;
}
```

**`mdopen(SMgrRelation)`** 

- 初始化 SMgrRelation 中的 md 特定字段
- 标记所有 fork 为未打开状态

**`mdopenfork(SMgrRelation, ForkNumber, behavior)`** 

- 实际打开第一个段文件
- 按需延迟打开

```c
static MdfdVec *
mdopenfork(SMgrRelation reln, ForkNumber forknum, int behavior)
{
	MdfdVec    *mdfd;
	char	   *path;
	File		fd;

	/* No work if already open */
	if (reln->md_num_open_segs[forknum] > 0)
		return &reln->md_seg_fds[forknum][0];

	path = relpath(reln->smgr_rlocator, forknum);

	fd = PathNameOpenFile(path, _mdfd_open_flags());

	if (fd < 0)
	{
		if ((behavior & EXTENSION_RETURN_NULL) &&
			FILE_POSSIBLY_DELETED(errno))
		{
			pfree(path);
			return NULL;
		}
		ereport(ERROR,
				(errcode_for_file_access(),
				 errmsg("could not open file \"%s\": %m", path)));
	}

	pfree(path);

	_fdvec_resize(reln, forknum, 1);
	mdfd = &reln->md_seg_fds[forknum][0];
	mdfd->mdfd_vfd = fd;
	mdfd->mdfd_segno = 0;

	Assert(_mdnblocks(reln, forknum, mdfd) <= ((BlockNumber) RELSEG_SIZE));

	return mdfd;
}
```

## 读写函数

**`smgrread()/smgrreadv()`**

- 从指定块读取数据到缓冲区
- 由 buffer manager 调用
- 支持向量化读取多个块

**`smgrwrite()/smgrwritev()`**

- 将缓冲区写入指定块
- 更新已存在的块，不扩展文件
- 异步写入，不保证立即落盘
- 需配合 checkpoint 机制保证持久化

**`smgrextend()`**

- 扩展关系，添加新块
- 在当前 EOF 位置或之后写入
- 更新缓存的块数量

**`mdextend()`**

- 底层实现：计算段内偏移
- 使用 `FileWrite()` 写入数据
- 注册脏段以便后续 fsync

**`smgrzeroextend()`**

- 一次扩展多个零块
- 比多次调用 extend 更高效

**`mdzeroextend()`** 

- 使用 `posix_fallocate()` 或 `FileZero()`
- 大扩展（>8块）优先用 fallocate，避免页缓存分配

#### 6. **预取与回写**

**`smgrprefetch(SMgrRelation, ForkNumber, BlockNumber, nblocks)`**

- 异步预取指定块
- 利用操作系统的预读机制

**`smgrwriteback(SMgrRelation, ForkNumber, BlockNumber, nblocks)`**

- 触发内核将脏页回写到磁盘
- 不等待完成，仅提示内核
